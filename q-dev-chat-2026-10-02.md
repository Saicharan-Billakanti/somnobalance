## PHASE 3 — DATABASE MIGRATION PLAN

### Critical Issue: `nodemailer` on Workers

Before writing any D1 migration, the **most blocking issue** is `nodemailer`. It uses Node.js `net`/`tls` sockets which are not available on Cloudflare Workers even with `nodejs_compat`. This must be replaced with an HTTP-based email service.

**Recommended:** [Resend](https://resend.com) (free tier: 3,000 emails/month) — simple fetch-based API, no native dependencies.

### Critical Issue: `bcryptjs` CPU limit

`bcryptjs` with cost factor 12 takes ~300ms of CPU time. Cloudflare Workers free tier has a **10ms CPU time limit**. The paid tier (Workers Paid) has a 30s limit. Options:
1. Use Workers Paid plan (recommended for production)
2. Lower bcrypt cost factor to 10 (still secure, ~75ms)
3. Migrate to `Web Crypto API` PBKDF2 for new passwords (can't re-hash existing ones without user re-login)

**Recommendation:** Keep bcryptjs at cost factor 10, use Workers Paid, and document this. Existing hashes stay valid.
